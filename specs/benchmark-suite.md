# EuroSetu benchmark suite — normative spec summary (§§3/4/6/7/9/10/13)

This document is the human-readable companion to the machine-enforced gates in
`.github/workflows/`. The suites themselves are the specification: every metric
on `/benchmarks` is generated by the exact released commit running these tests.

## 1. Canonical contracts (§3)

- Schema version `EUROSETU_CANONICAL_V1` (`app/canonical_models.py`), persisted
  on every transaction, evidence object, source snapshot, obligation and decision.
- Decision policy `DECISION_POLICY_V1` (`app/decision_engine.py`): fail-closed
  aggregation ERROR → BLOCKED → CONDITIONAL → READY. Policy changes never
  rewrite historical decisions (each pins `policy_version` + snapshot hashes).
- Evidence lifecycle (§3.3, §5.11): seven states
  VALID / STALE / EXPIRED / UNVERIFIED / CONFLICTING / SUPERSEDED / MISSING,
  evaluated against a deterministic `as_of` clock (`app/evidence_lifecycle.py`).
- Source registry (§2.1): immutable versioned snapshots; point-in-time compile
  uses only snapshots effective at `as_of` (`app/source_registry.py`).

## 2. Harness (§4)

Shared harness `app/benchmark_harness.py`: fixture manifest → compare (dotted
paths + tolerances) → emit (`benchmark-result.json`, `metrics.json`,
`report.md`, `decisions/`) → `assert_and_emit` (CI asserts on FAIL). Every run
records `code_commit`, `schema_version`, `as_of`, durations and the full
assertion table. Helpers in `tests/benchmarks/helpers.py`.

## 3. APIs (§7)

Versioned prefix `/v1` (`app/v1_api.py`): transactions (idempotent by
`transaction_ref`), evidence, source snapshots, `market-access/check` (requires
`as_of`; merges caller obligations with server-evaluated CBAM/TARIC payloads),
decision fetch, decision replay (pinned refs only), impact, remediation.
Internal `POST /internal/benchmarks/run` for CI orchestration.

1. unknown schema → ERROR, never reused; 2. MISSING → BLOCKED;

5. missing oracle raises before PASS.

## 5. Public proof (§10, §13 DoD)

- `/benchmarks` renders ONLY released bundles under `web/benchmarks/<commit>/`
  produced by `scripts/release_benchmarks.py` (runs suites → keeps latest PASS
  per case → redacts §14 patterns → writes `results.json` + `summary.json`).
- No public metric unless generated by the exact commit shown. No competitor
  logos. Every metric links to its case artifact. Evidence classes labelled
  NORMATIVE / EXTERNAL-ORACLE / COMPETITIVE-SCENARIO / SYNTHETIC.
- Adjacent notice on every surface: engineering assurance / benchmark
  validation, not legal certification.
- `scripts/lint_claims.py` fails the build on forbidden positive claims
  (authority-certification language, incumbent-replacement language,
  competitor-parity language, guaranteed-outcome language — see the script
  for the exact patterns).
- Case study (`/case-study`, §11): five linked views Order → Rules → Evidence →
  Decision → Audit on synthetic order SYN-PO-HRC-001 (€340k illustrative).
  Add-evidence creates new objects; Recompile creates a new Decision with
  `predecessor_id`; the causal change is displayed; replay re-aggregates pinned
  snapshots.

## 6. CI map

- `ci.yml` (every push/PR): unit + web smoke, P0 benchmarks, P1 benchmarks
  (excluding scale), fail-closed, claim lint. All required.
- `nightly.yml` (schedule + manual): full suite including `scale`, plus source
  content validation. Required green before any release tag.
- `benchmark-release.yml` (version tags `v*`): re-runs full suite, runs
  `release_benchmarks.py` (no `--skip-tests`), uploads `web/benchmarks/<sha>/`
  as the release artifact. The bundle is committed to publish `/benchmarks`.
